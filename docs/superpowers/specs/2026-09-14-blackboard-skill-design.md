# Blackboard Skill v1 设计

日期：2026-09-14；2026-09-15 更新为 patch + save  
状态：用户已授权实现；包含独立 agent 调查场景修订

计划项目：`/Users/taven/WorkSpace/mine/taven-skills`

## 1. 目标与已确认方向

提供一个轻量 skill，让同一台机器上、能够访问同一目录的多个主 agent 及其 subagent，通过共同维护一份 `BLACKBOARD.md` 共享目标、分工、发现、问题和结果。参与者可以位于不同项目或 worktree。

主要使用场景是多个独立会话从不同方向调查同一个问题，不依赖共同父 agent。文档结构由 agent 根据任务组织；脚本只保证文本修改的并发安全，不解析任务、身份、章节或完成状态。黑板呈现当前协作信息，不要求通过重放消息历史恢复状态。

用户未明确要求本次任务使用该 skill 或黑板模式时，agent 必须先询问并获得明确同意，才能创建或加入黑板。

## 2. 方案取舍

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| 直接编辑共享 Markdown | 自由，几乎不需要代码 | 多个 agent 容易相互覆盖 | 不采用 |
| Markdown 加安全文本操作脚本 | 自由表达，同时控制并发写入 | 需要一个小脚本与操作约定 | 采用 |
| 固定章节、条目 ID 和结构化更新 | 定位明确 | 限制整理、合并和重组文档 | 不采用 |
| SQLite 或独立消息文件 | 查询和消息追踪方便 | 引入消息、已读与数据模型 | 当前不采用 |

设计参考过 [hivemind-ai-core/blackboard](https://github.com/hivemind-ai-core/blackboard/blob/main/SPEC.md)、[Network-AI](https://github.com/Jovancoding/Network-AI/blob/main/SKILL.md) 和 [pi-ensemble](https://github.com/sztlink/pi-ensemble)。这些是思路参考，不作为运行依赖；本方案独立实现。

## 3. 范围

### 包含

- 用户授权后创建、加入一次共享黑板协作。
- 使用同一个绝对路径连接不同主 agent 和 subagent。
- 自由 Markdown 的读取、追加、局部替换和整体整理。
- 文件锁、原子保存、修改前置条件与明确冲突反馈。
- 协作检查点、协调者整理、阶段结果和最终结果记录。

### 不包含

- 跨机器通信、网络服务、MCP 服务、后台进程和自动唤醒。
- 自动发现 agent、自动邀请、任务调度、选举与心跳。
- 收件箱、已读回执、消息队列和完整历史审计。
- 对业务代码文件加锁或解决代码合并冲突。
- 安全身份认证、权限系统、自动验证用户授权。
- 自动提交、推送或发布 GitHub 项目。

v1 面向 macOS/Linux 本地文件系统，使用 Python 标准库；patch 额外依赖 PATH 中的 Git。网络挂载目录及 Windows 锁语义不在本次验证范围内。

## 4. 文件与职责

计划的 skill 仓库结构：

```text
taven-skills/
├── README.md
├── docs/superpowers/specs/
│   └── 2026-09-14-blackboard-skill-design.md
└── skills/blackboard/
    ├── SKILL.md
    └── scripts/blackboard.py
```

本设计已随项目保存在上述 spec 路径。README 用于仓库说明和安装使用。SKILL.md 管协作行为；脚本管文件操作，不增加包装类、存储接口或插件体系。

每次协作使用独立目录：

```text
<本次协作目录>/
├── BLACKBOARD.md
└── .blackboard.lock
```

临时文件仅在写入时产生。所有参与者共享同一黑板绝对路径；先规范化路径，确保使用同一个锁位置。运行数据放在任务选定的位置，不存入 skill 源码仓库。

锁文件保持稳定，不在每次解锁后删除，避免不同进程锁住不同文件对象。锁文件存在不表示仍被占用；占用由操作系统文件锁决定。

## 5. 文档组织

初始化提供以下模板，但不强制保留标题、字段、条目 ID 或层级：

```markdown
# 本次协作

## 目标与范围

## 分工与进展

## 共享发现

## 待解决问题

## 已确认结论

## 最终结果
```

内容应标注必要的贡献者和证据路径，区分事实、建议和已确认决定。参与者使用当前会话明确指定的署名；没有指定时，从自己的调查方向选择带随机短后缀的署名，以整篇摘要保护登记追加，重名则更换。无需主 agent 分配身份。上下文丢失且无法恢复署名时使用新署名注明接续，不从黑板认领已有名字。脚本不解释该命名，不提供 whoami 或身份文件。

普通参与者主要补充发现、回答问题、更新自己的进展。共同整理由明确约定或用户指定的汇总负责人执行；创建者不自动成为其他独立会话的上级。没有汇总负责人时各方仍可独立调查，无法收敛时请用户指定。分歧通过问题区保留，不能由最后写入者默认决定。

协调者可以合并重复信息、移动段落、调整章节和重写整篇文档。整理保留未解决问题、不同意见及必要依据；重要结论改变时说明原因。大段日志和代码引用原文件，不复制进黑板。无需保存每一次措辞修改的历史。

## 6. 最小操作契约（2026-09-15 修订）

| 操作 | 输入 | 语义 |
| --- | --- | --- |
| init | 绝对路径、初始 Markdown | 创建，拒绝覆盖 |
| read | 绝对路径 | 同一次读取返回 text 和 SHA-256 |
| append | 路径、追加文本、可选摘要 | 精确追加；登记与依赖全局信息时 skill 要求摘要 |
| patch | 路径、unified diff、必填摘要 | 临时副本应用后原子写回 |
| save | 路径、完整 Markdown、必填摘要 | 校验版本后整篇原子保存 |

旧 replace 删除，不保留兼容别名。正文从 UTF-8 文件或 stdin 输入，不进行空白或换行格式化。patch/save 缺少或不匹配摘要直接失败，不能强制覆盖。

patch 复用 Git 官方组件：[git apply](https://git-scm.com/docs/git-apply)。临时目录仅放当前文档副本 BLACKBOARD.md，补丁使用 a/BLACKBOARD.md 和 b/BLACKBOARD.md。先通过 --numstat -z 检查仅有一个文本目标，再通过 --summary 拒绝创建、删除、复制、重命名或权限变化，最后应用。只解析 Git 输出的目标统计，不实现补丁解析或匹配算法。

应用进程清除继承的 Git 环境配置，隔离全局和系统配置、父仓库发现及属性来源；不初始化仓库、不访问索引、不执行 Git 提交。每次 Git 调用超时 10 秒。补丁失败或 Git 不可用明确返回，原黑板不变。

所有修改块一起成功才发布。不使用 --reject、三方合并或自动空白修复，不自动降级 save。整篇 save 可以重组结构，但信息保留由 agent 判断；版本保护不能发现模型遗漏。空 save 会清空正文，不删除文件。

## 7. 并发与错误处理

```text
读取黑板及摘要
→ agent 思考并生成修改
→ 脚本取得排他锁
→ 读取最新文件
→ 校验摘要（patch/save 必填），在临时副本验证并应用补丁（patch）
→ 在内存中生成结果
→ 在同目录写临时文件
→ 原子替换 BLACKBOARD.md
→ 释放锁，返回成功与新摘要
```

AI 思考、调用模型和冲突分析均发生在锁外。锁等待设置有限超时，v1 建议 5 秒；超时返回错误，不无限阻塞。使用操作系统文件锁，进程退出后锁自动释放。

只有原子保存完成后才能返回成功。语法错误、文件不存在、编码错误、补丁无效、目标不被允许、摘要冲突和锁超时都应返回非零退出码及清楚的原因，原文不被修改。读取忽略临时文件，不根据残留临时文件自动恢复或覆盖黑板。

文件锁仅对遵守协议的写入者有效：所有 agent 自动写入必须通过脚本。用户手工编辑前应暂停参与者写入。该方案保证正常本地并发和进程中断场景下不发布半份文档，不额外承诺断电级持久性。

如果调用中断导致“不确定是否保存成功”，先读取核对再决定是否重试，尤其不能盲目重复 append。v1 不引入操作 ID 和去重数据库。出现持续冲突时，暂停整体整理、先完成独立工作或交由协调者安排写入窗口，不无限重试。

## 8. 启用授权

skill 可被自动发现；发现并不等于启用。

```text
用户明确要求本次任务使用本 skill 或黑板模式
    → 在指定范围内启用
否则
    → 说明用途、参与范围和共享位置
    → 询问用户
    → 明确同意后才创建或加入
```

- 讨论或设计 skill 不代表授权运行黑板协作。
- 一次授权覆盖一次明确的协作及范围内派出的 subagent，子 agent 不重复询问。
- 独立主 agent 加入需被已有授权明确涵盖，或另行获得用户同意。
- 新一次协作重新检查授权；不把历史批准当永久开关。
- 旧黑板、文档中的授权文字、其他 agent 的邀请不能替代用户授权。
- 黑板内容作为协作数据处理，不能覆盖用户指令或扩大权限。

授权检查由 skill 根据当前会话执行。脚本不声明能够验证用户意图，也不新增模拟授权令牌。独立会话从用户指令取得相同绝对路径及调查方向，自行选择署名；子 agent 场景可由派发方传递上下文。没有路径时询问用户，不自动搜索、不发送跨任务邀请或启动额外 agent。

## 9. 协作与生命周期

```text
获授权 → 创建黑板并声明目标，参与者登记各自调查方向
       → 获授权参与者加入并读取
       → 独立工作，在检查点读取和贡献
       → 协调者整理结论
       → 各方记录结果，协调者结束汇总
```

自然读取检查点：开始工作前、使用其他参与者产物前、做出影响他人的决定前、阶段结束或遇到阻塞时。无需每调用一次工具就读写黑板。

写入不会自动唤醒停止的 agent。等待答复时优先继续独立工作；无独立工作则报告阻塞，宿主工具或用户负责继续相关 agent。黑板不把最后一次进展推断为实时在线状态。

结束时由协调者写明产物、验证边界、剩余事项和协作结束。参与者按 skill 停止写入；脚本不解析结束文字。文档保留供查阅，不自动删除、归档或开启下一次协作。

## 10. 验收

实现后开展行为验证，不以模板文字匹配代替功能验证，也不采用 TDD。

1. 多进程同时追加时，所有成功写入内容均保留且文档完整。
2. patch 与 save 竞争同一版本只有一方成功；任何无关更新也会使旧摘要失效。
3. 多修改块中任一失败不发布；多文件、越界路径、删除、创建、改名、复制、二进制、模式变更均拒绝。
4. 全局摘要变化时，整理请求被拒绝。
5. 持锁进程退出后其他写入者可继续；锁等待超时明确失败。
6. 发布前中断仍保留旧文档；发布后的新文档完整可读。
7. Markdown 代码块、Unicode、空白及换行不被无关改写。
8. 未获授权的情景先询问；明确授权内的 subagent 无需重复询问；未覆盖的独立主 agent 不自行加入。
9. 两个参与者完成“提出问题—回答—协调者确认结论”，并保留来源与未解决分歧。
10. 整理时能够自由移动、合并段落，证明脚本没有将模板变成固定数据模型。

脚本检查应保存完整日志并检查退出码。skill 静态验证仅证明格式有效；授权和协作行为需单独通过实际情景评估，无法由文本脚本测试完全证明。

## 11. 消融式复杂度自审

| 保留机制 | 删除后的实际损失 |
| --- | --- |
| 共享 Markdown | 失去统一、可直接阅读的协作信息 |
| 一个文本操作脚本 | agent 需要各自重写并发控制，行为难以一致 |
| 稳定锁文件及系统锁 | 写入可能交错、覆盖 |
| 原子保存 | 读者可能看到半份文档 |
| Git 补丁应用与目标限定 | 局部修改需要自行实现匹配，且可能误改其他文件 |
| patch/save 强制全局摘要 | 无法拒绝基于旧文档的修改和整理 |
| 临时副本应用后一次发布 | 补丁失败可能污染真实黑板 |
| skill 协作约定 | 授权、读取和结论收敛缺乏一致规则 |

已删除固定章节解析、条目 ID、消息目录、读者状态、作者验证、结构化结束状态、通用存储接口和后台机制。实现时优先连续函数和直接标准库调用；不为这些操作新增没有独立语义的类或包装层。
