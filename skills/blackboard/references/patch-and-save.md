# patch 与 save 细则

需要修改黑板已有内容时读本文件。两者都必须带刚 `read` 得到的 `--expected-sha256`。

## patch

`patch` 接收标准 unified diff，不是 apply_patch 工具的 `*** Begin Patch` 格式。补丁路径固定为 `a/BLACKBOARD.md` 和 `b/BLACKBOARD.md`，即使真实黑板文件使用其他名字也是如此；脚本将真实内容复制到这个临时文件。保留足够上下文及正确的修改块行数，例如：

```diff
--- a/BLACKBOARD.md
+++ b/BLACKBOARD.md
@@ -1,3 +1,3 @@
 # 调查
 
-日志调查：等待证据。
+日志调查：超时位置已确认，见 trace.log。
```

脚本使用 `git apply` 解析和应用补丁，不实现补丁匹配器。仅接受一份文件的文本修改；拒绝其他路径、多文件、创建、删除、重命名、复制、二进制及权限修改。可删除文档的所有文字，但不能删除文件本身。临时副本上应用成功后才原子写回；任何修改块失败都不写回，不使用 reject、三方合并或自动空白修复。

## save

`save` 输入为完整新 Markdown，不需要输出旧正文。适合整篇整理；必须保留其他参与者的有效证据、未解决问题和分歧。脚本只校验版本，无法判断模型是否遗漏信息。空输入表示将文档清空，只有明确需要清空时才这样调用。
